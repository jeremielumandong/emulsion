FOR PHOTOGRAPHERS

Develop the photo.
Keep the original.

Open supported camera RAW files and work from sensor data. Tune exposure, temperature, tint, shadows, contrast, saturation, and highlight rolloff before bringing the image into your composition.

  1. Start with Auto tone, Pick neutral white balance, or the camera’s as-shot white balance.
  2. Refine luminance curves and inspect your changes with the draggable before/after divider.
  3. Save development settings in an Emulsion JSON sidecar, or save an ORA project for layers and history.

RAW camera support varies. Keep the original RAW alongside its sidecar or linked project; ORA does not embed the source.

01 / Getting started

Emulsion is an actively developed desktop image editor built in Rust with GPUI for Linux, macOS, and Windows. Its original code is MIT licensed. Painting and editing work without an AI account.

Build from the repository using the instructions for your platform. Linux requires Rust, the GPUI system libraries, and a working graphics driver; Windows requires the MSVC Rust toolchain and Visual Studio C++ Build Tools; macOS packaging requires Rust and the standard icon tools.

Open an image, reopen a recent project, or choose New transparent canvas. Save layered work as .ora; use Export to create an image for sharing.

Full build requirements →

02 / Painting, retouching, and layers

Choose a tool on the left and adjust its options above the canvas. Use brushes and erasers for painting, clone and heal for retouching, or smudge, gradients, and liquify to reshape the image. Add a selection or mask when an edit should affect only part of the artwork.

The right dock keeps Layers visible. Use + Layer → Empty layer or Ctrl + Shift + N for a transparent layer. Add groups, duplicate layers, and combine raster artwork with editable text and paths. Properties holds transforms, blending, and masks.

Choose Grade for exposure, curves, colour balance, and hue/saturation adjustment layers. Select an existing adjustment layer to edit its controls. Add references through the Reference panel to keep an image beside your canvas; references belong to the open session and must be reattached after reopening.

All editor controls →

03 / Developing and saving RAW photos

Open a supported RAW file to develop its sensor data. Use Adjust for tone and white balance, Curve for presets and five editable luminance points, and Settings for presets, sidecars, camera defaults, and selected-photo synchronization.

Choose Before / after in RAW Properties to compare as-shot development with your edits using a draggable divider. With the canvas focused, Left/Right and Home/End move the divider; Escape closes comparison.

For a directly opened RAW photo, Save writes <filename>.emulsion-raw.json beside the source without modifying it. Reopening the original restores these settings. Sidecars contain the current RAW recipe, not history, and are not Adobe XMP.

Use Save as → .ora to preserve layers, history, and versioned RAW settings. Keep the original: the project stores a verified link, not an embedded RAW. Use Locate original… if an identical source has moved. Paint on a separate layer to keep RAW development editable.

The working raster is 16-bit linear RGB, not a wide-gamut floating-point document. Monitor-profile conversion, lens profiles, advanced RAW noise reduction, and saturated-highlight reconstruction are not included in this development path.

RAW saving, export, and limitations →

04 / Recipes and batch export

Open Panels → Recipes. The Emulsion collection holds starter recipes, camera presets, and saved looks. Other collection chips open the community library, grouped by film simulation family. Use tags to narrow a collection; each library recipe retains its creator and source in its notes.

In Batch, choose a folder in the top bar and select photos in the left pane. Search the recipe chooser by name or tag, or expand Category for a filter. Set the format and output folder in the right dock, then select Export in the top bar.

Batch controls reference →

05 / History, project files, and replay

Use undo, redo, and history branches to explore alternatives. Save an OpenRaster (.ora) project to retain editable work and history. Emulsion’s native data keeps text and paths editable; other OpenRaster readers can use the included layer previews. Newly saved native version 2 projects require an updated Emulsion build for native editing.

Open Panels → Timeline → Replay drawing to play the picture back from its history and export a GIF. Leaving Timeline stops playback and returns to the full document.

Export is a delivery step; keep an ORA project when you want to return to editable work. RAW sidecars only preserve development settings, so use ORA when your work needs layers, named versions, or undo history.

06 / Bringing files in and sending them out

Common formats and what to expect
WorkflowFormats and support
Editable projectsSave native work as ORA. Open layered PSD/PSB and supported 8-bit GIMP XCF files. Import fidelity depends on the source features.
Photos and artworkOpen PNG, JPEG, WebP, TIFF, BMP, GIF, SVG/SVGZ, JPEG XL, OpenEXR, and more. Camera RAW support varies by camera, model, and compression.
Common exportsPNG, JPEG, WebP, and TIFF; PNG/TIFF support 16-bit output. Linked RAW exports offer sRGB or Adobe RGB profiles and full, half, or quarter sizes.
Layered exportsLayered PSD and 8-bit XCF. XCF exports visible top-level layers with adjustments, masks, and styles baked into each layer; hidden layers are omitted.
Extra convertersHEIC/HEIF, AVIF, PDF/PostScript import, and other formats can use installed external converters. AVIF, HEIC, JPEG XL, and PDF export also require external tools. Flatpak cannot use host converters.

CMYK sources are converted to RGB for editing, with support depending on format and profile. CMYK PSD/PSB support is limited to the saved merged appearance for supported 8-bit files. Projects and exports retain RGB pixels, not CMYK ink separations. Formats without transparency composite over white.

07 / Optional assistant and image generation

An assistant that uses editing tools

Install and authenticate a supported Claude Code, Codex, OpenCode, or Kimi Code CLI, then open F1 → Assistant. Ask it to inspect the canvas, use a reference, build artwork, adjust colours, or automate a recipe. Review proposed document changes with Apply/Skip. Model access or a provider subscription is not bundled.

Emulsion connects its MCP server to the active app so the assistant can call editing operations directly. Starting emulsion mcp-serve alone exposes the tool catalog but cannot edit an open document without that connection.

Generate an image or fill a selection

Configure Settings → Image generation, then choose Local SD, OpenAI, or Google from F1. Local SD uses an A1111/Forge API server. Cloud providers require their own API keys and separately billed access. Enter a prompt; generated results arrive as labeled raster layers you can hide or undo. With an active selection, generation uses the surrounding canvas as context.

Cloud generation sends prompts and fill context to the selected provider. Save & test checks key/model access, not generation quota. Cancelling discards the result but does not guarantee cancellation of provider processing or charges. Attached references are available to Assistant; image modes use the prompt and selected canvas context.

Optional subject selection, background removal, inpainting, face restoration, and upscaling require the relevant models or providers to be configured.

08 / Workspace and shortcuts

Choose light or dark mode from the top bar. On Linux, the Omarchy control can follow the active desktop theme without changing document pixels. Settings → Layout → compact chrome reduces the top bars to leave more height for the canvas.

Open Navigator, Info, Recipes, Timeline, History, or Histogram from Panels. Tool buttons support Tab navigation and Enter/Space activation. Focused sliders accept arrows, Shift+arrow for larger steps, and Home/End for limits.
