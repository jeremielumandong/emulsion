# MCP inventory audit - 2026-09-30

The starting registry contained 359 tools. This audit adds five tools, for **364 registered tools**, plus missing actions on three existing tools. The [complete JSON inventory](data/mcp-audit-2026-09-30.json) is generated from `emulsion_mcp::tools::definitions()`, the same registry exposed by `tools/list`.

## Coverage and changes

| Gap | Implemented coverage |
| --- | --- |
| Individual Library photo import | `add_library_photos` takes explicit absolute paths and optional content deduplication. It awaits background catalog persistence. |
| Library reload | `refresh_library` reloads the catalog, saved settings and previews, retaining selection, filters and unsaved drafts. |
| Removing Library photos | `remove_library_photos` takes explicit canonical paths, cleans catalog memberships and folder rows, and keeps original files, sidecars and pending drafts. |
| Collection maintenance | `library_collection` now supports rename, remove membership and delete, in addition to create/add. Deleting the active collection resets its filter. Smart collection membership edits return an explanation rather than pretending to override the rule. |
| Snapshot deletion | `develop_library(action="delete_snapshot", name=...)` deletes the named snapshot while retaining settings/history. Snapshot writes share the UI save guard, clear it on failure and resume pending autosave. |
| Before/after divider | `set_library_view(comparison_position=...)` exposes the shared preview divider; `get_library` reports its state. |
| Opening existing artwork | `open_workspace_file` decodes local images, layered artwork, native projects and supported editable imports in the background. It returns the opened tab after installation, preserves relay identity and unsaved tabs, and reuses already-open native files without replacing their edits. RAW sources use the Library tools. |
| Photo/Paint canvas creation | `create_canvas` creates Photo, Paint, Design or Diagram tabs using native size/unit/resolution/depth/background validation. It preserves existing tabs and relay origin; Paint activates drawing tools. |
| Progress inspection | `get_library` reports import, removal and reload jobs; mutating calls reject conflicting jobs, and new operations await completion. |
| Offline dispatch diagnostics | Diagram-project, reference-attachment and presentation tools explicitly identify their live-host requirement. |
| Registration drift | Added an executable inventory and recursive schema/policy checks, including all destructive classification lists and host-only offline dispatch. |

New path-taking tools reject empty, relative, duplicate and oversized path lists. Collection and snapshot actions reject mismatched arguments. Removal actions participate in the existing assistant confirmation policy.

## Reproduce

```powershell
cargo run -p emulsion-mcp --example audit --locked
cargo test -p emulsion-mcp --lib --locked
$env:CARGO_INCREMENTAL = '0'
$env:RUST_MIN_STACK = '33554432'
cargo test -p emulsion-ui --lib --locked --config 'profile.dev.package.emulsion-ui.opt-level=0' --config 'profile.dev.package.emulsion-ui.debug=0' -- mcp_ --test-threads=1
cargo clippy -p emulsion-mcp -p emulsion-ui --lib --locked --no-deps
```

The audit command prints each tool's name, description, schema, read-only classification, explicit confirmation policy and required execution environment. It exits unsuccessfully if structural checks find problems. It does not execute tools, load personal artwork, send requests to providers or submit print jobs.

The inventory checks cover every registered tool: unique names, object schemas, required-property references, nested bounds/enums, missing classified names and conflicting read-only/destructive policies. Dedicated tests exercise all live-only offline routes. Existing module and relay tests cover native commands and `tools/list` annotations; new live integration tests cover added Library and workspace operations.

## Verification

- Full MCP library suite: **216 passed**, including all registration/schema/policy audit checks, offline host diagnostics and the new argument tests.
- Formatting check for the changed Rust files: passed.
- Executable inventory: **364 tools**, **117 requiring a live workspace**, **67 read-only**, **zero structural/policy issues**.
- Clippy for MCP and UI libraries: passed; existing dead-code warnings remain in IO and engine dependencies.
- Live MCP integration tests: **17 passed**, covering Library lifecycle/persistence, workspace creation, local file opening, stale relay rejection, native project history and existing RAW/diagram relay workflows.
- Patch whitespace check: passed.

The first full run exposed a Unix-only HDR test fixture on Windows; it now uses native absolute temporary paths. Reference-image diagnostics retain their shared implementation across execution paths. The Library relay fixture now uses canonical Windows paths, as required by the selection API. Initial catalog loading is awaited before selection; import/removal conflicts are still rejected. A one-line IO result annotation also fixed a compiler error in the concurrently edited diagram import UI.

## Boundaries

This is an inventory, contract and workflow audit; it does not claim that every tool was manually exercised with every format or platform runtime. AI providers/models, printer devices, media runtimes and cloud credentials still require their normal setup. OS driver/queue administration, account configuration, desktop file associations and unsupported native features are not silently exposed as new tools. See [workflow coverage](mcp-coverage.md) for the broader mapping and limitations.
