# Editable Lottie interchange

In Design → Animate, **Import Lottie animation** places a JSON animation as native objects in one Undo step. **Export Lottie · editable vectors** exports the supported native subset without flattening it. **Export Lottie · rendered frames** remains an explicit appearance fallback. Open-file import also recognizes Lottie JSON by its composition fields; ZIP `.lottie` packages are not supported.

Imported paths keep editable cubic anchors and handles. Rectangles, ellipses, compound paths, shape groups, solid fills, strokes, linear/radial gradient stops, ordinary text and embedded images become native objects. Layer start/end times become visibility tracks. Top-level 2D position, anchor, positive scale, rotation and opacity animation become native property keyframes. Cubic temporal easing and spatial position tangents are evaluated and sampled to at most 64 editable keys per property. Import extends destination page duration as required, preserves destination dimensions, and does not overwrite existing objects. Save as `.emu` to retain native editing and Undo history.

The import report names features which need review. Animated paths, paint, shape-group transforms and nested-precomposition transforms currently use initial values. Animated parent transforms use their initial value. Transform animation requiring shear also uses its initial transform. Masks, mattes, effects, repeaters, trim paths and unknown operators are diagnosed. Gradient stop colors/alpha remain editable; gradient endpoints fit native shape bounds. Rounded-rectangle radius and stroke dashes are diagnosed on import. Text uses installed font families; advanced animators and exact cross-player baseline metrics are not preserved. External images and fonts are never fetched. Embed image data before importing.

Editable export writes standard shape layers with cubic paths, fills, strokes, gradient stops, groups/precompositions, ordinary text, and embedded image layers. Native translation/rotation/opacity tracks retain their timing and supported easing. Independent scale channels are sampled at the saved frame rate into editable transform keys; visibility combines with opacity. Simultaneously animated parents and children require rendered-frame export because native child transforms compose in world axes. Unsupported masks, effects, clipping, pattern paint, stroke alignment, advanced typography, placed-image transforms, legacy entrance/exit effects and text reveal produce an error directing the user to rendered-frame export. They are never silently flattened by editable export.

Rendered-frame export writes embedded PNG image layers, deduplicating identical frames, at up to 1024 pixels on the longest side. It is useful for appearance exchange, but does not retain editable vectors. All exports cover the active page only; presentation actions, slide transitions and audio/video playback are excluded.

Limits: JSON/export size 64 MiB, embedded image payload 32 MiB, 16 megapixels per image and 32 megapixels total on import, 2,000 imported objects, 512 layers per composition, 16 composition nesting levels, 32 shape-group nesting levels, 20,000 anchors per native path. Native keyframe limits also apply: 256 animated objects, 4,096 points total, 64 points per property. Compositions must be 100 ms–60 s at 1–60 fps; exports support up to 600 frames. Invalid references, cycles and malformed data reject the import before the current document changes.

MCP exposes `import_design_lottie {path}` and `export_design_motion {path, format}` with `lottie`, `lottie_raster` or `animated_svg`. Reports include unsupported-feature diagnostics. Import uses the same one-step Undo as the native UI.

Interchange follows the public [Lottie layer specification](https://lottie.github.io/lottie-spec/latest/specs/layers/), [shape specification](https://lottie.github.io/lottie-spec/latest/specs/shapes/) and [animated property specification](https://lottie.github.io/lottie-spec/latest/specs/properties/). This is a documented editable subset, not full compatibility with every Lottie authoring tool.

Validation includes an independently authored cubic-path JSON fixture, native group/gradient/compound-hole/text/image roundtrips, layer timing, Undo, stale picker responses and project persistence. A Linux browser smoke check with the official lottie-web 5.13.0 player rendered an exported animated square as one SVG path with no image layers: x=10, 50 and 89.42 at frames 0, 10 and 19, retaining its 30×20 dimensions. The test player is downloaded separately for verification and is not shipped with Emulsion. Windows/macOS runtime acceptance remains a separate check.
