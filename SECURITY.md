# Security policy

## Reporting a vulnerability

Please report suspected vulnerabilities through
[GitHub private vulnerability reporting](https://github.com/jeremielumandong/emulsion/security/advisories/new).
Do not open a public issue or pull request containing vulnerability details,
exploit files, or credentials.

Private reporting must be enabled by the repository maintainer for that link to
work. If it is unavailable, open an issue asking only for a private security
contact, without disclosing the vulnerability or affected details.

Include:

- The affected version or commit, operating system, and relevant configuration.
- Reproduction steps and a minimal proof of concept, where possible.
- Expected and actual behavior, potential impact, and any suggested fix.

Use synthetic examples where possible. Do not include real API keys, personal
photos, or other private data. Coordinate disclosure with the maintainer while
the report is investigated and a fix is prepared. Response and fix timelines
depend on maintainer availability and the issue's scope.

## Supported code

Emulsion is under active development. Security fixes target the current `main`
branch; older commits and releases do not have a separate security maintenance
commitment. Include your exact commit or version when reporting an issue.
